# نطاق الإصدار الأول — O13
تاريخ المناقشة: 2026-11-24 UTC. هذه خلاصة ستة قرارات اتجاهية من المالك وتفويضه الهندسي، وليست اعتمادًا نهائيًا للتقنية أو إثباتًا للجاهزية. المراجعة المستقلة التفصيلية معلقة.

## R01 — المنصات
أندرويد للهاتف واللوحي، ويندوز، والويب ضمن الإصدار الأول، لا يؤجل الويب إلى إصدار لاحق. محرك أعمال مشترك وقواعد موحدة وواجهات متكيفة. يختبر دعم المنصات الثلاث قبل اختيار التقنية. لا يفترض تطابق إمكانات التخزين والعمل دون اتصال والطباعة بينها.

## R02 — الأنشطة
التجزئة والجملة والخدمات والأنشطة المختلطة. قوالب إعداد قابلة للتخصيص وتفعيل الوظائف بحسب الحاجة دون تقييد المنشأة بنشاط واحد. اختيار هندسي مفوض من المالك، وليس اعتمادًا لكل تفاصيل القوالب.

## R03 — التشغيل
جهاز مستقل دون إنترنت، عدة أجهزة عبر الشبكة المحلية، وربط خارجي اختياري للفروع والمستخدمين المخولين. انتقال بين الأنماط دون إعادة تأسيس المنشأة. لا اشتراك سحابي إلزامي للوظائف الأساسية. تحدد حدود العمل دون اتصال لكل منصة وتختبر. اختيار هندسي مفوض؛ بروتوكول المزامنة والسلطة والتعارضات مسائل مفتوحة.

## R04 — الوظائف
| القسم | نطاق الإصدار الأول |
|---|---|
| التجارة | المبيعات والمشتريات والمرتجعات والتسعير |
| المخزون | المستودعات والجرد والتحويلات والنواقص |
| المحاسبة | الحسابات والقيود والأرباح والتقارير المالية والمصروفات |
| الخزينة | الصناديق والبنوك والمحافظ والعملات |
| العلاقات التجارية | العملاء والموردون والديون والالتزامات |
| الإدارة | الشركات والفروع والموظفون والصلاحيات |
| الإدارة الذكية | التنبيهات والتحليلات والتوصيات والأتمتة الأساسية |
| البنية التقنية | المزامنة والأمان والنسخ الاحتياطي والطباعة والتخصيص |
الأصناف والوحدات والتصنيفات والإعدادات والبحث قدرات مشتركة. لا تعني الأقسام ثمانية تطبيقات أو قواعد بيانات مستقلة. الذكاء الاصطناعي الخارجي والتنبؤات والأتمتة المتقدمة ليست شرطًا للإصدار الأول. تفاصيل قبول كل وظيفة تحتاج تفصيلًا قبل تنفيذها.

## R05 — معايير القبول
- البحث عن الأصناف: أقل من 500 مللي ثانية.
- اعتماد البيع محليًا: أقل من ثانية، دون انتظار الطباعة أو الشبكة.
- لا قيود غير متوازنة؛ اختبار التراجع الذري والدقة.
- استمرار الوظائف الأساسية دون إنترنت وفق حدود كل منصة.
- منع تكرار الأثر المالي عند إعادة المحاولة والمزامنة.
- قياس عدد الضغطات في تدفقات العمل اليومية وتقليله دون حذف ضوابط لازمة.
- اختبار استعادة النسخ الاحتياطية فعليًا.
- اتساق النتائج بين المنصات الثلاث.
- عزل المنشآت والتحقق من الصلاحيات في الخدمات.
الأرقام أهداف مقترحة وليست قياسات. قبل التجربة تحدد الأجهزة وحجم البيانات وحالات القياس والتكرار ومقياس التوزيع وحدود العمل دون اتصال. لا يدعى تحققها قبل القياس.

## R06 — ترتيب التنفيذ الموحد
هذا الترتيب يفصل **بوابات ما قبل الإثبات** عن **تنفيذ المنتج بعد اختيار التقنية**؛ لا يعني أن مقارنة التقنيتين تسبق التصميم والمراجعة.
1. فحص الوثائق والتصحيحات والموروث ضمن ضوابط CORE-005، وإغلاق اعتراضات المراجعة المانعة؛ توثيق الأدلة الخاصة دون نشر كود V2.
2. حسم سياسات الاختبار المحدودة ونطاق الإثبات ومعايير المقارنة؛ لا تحويل فرضيات الاختبار إلى قرارات تجارية.
3. تنفيذ إثباتين تقنيين معزولين ومتكافئين: معرفات وقيم مالية وكمية دقيقة وسياق اختبار موثوق ونتيجة بسيطة، ثم أمر محلي واحد يثبت الذرية ومنع التكرار والتزامن وإعادة الفتح. لا بناء ثمانية محركات عامة ولا اعتبار هذه التجربة تطبيقًا إنتاجيًا.
4. تشغيل بناء واختبارات حقيقية لأندرويد وويندوز والويب، والتحقق من التخزين دون اتصال والقيود العملية؛ مقارنة النتائج قبل اعتماد التقنية.
5. بعد اعتماد الاختيار: تأسيس النواة الإنتاجية ومخزن البيانات، ثم المحركات التجارية والمالية والمخزون وفق حدود المسؤوليات.
6. بناء الواجهات وتجربة الاستخدام والتكامل والمزامنة والإدارة الذكية تدريجيًا مع الاختبارات في كل مرحلة.
7. التحقق الشامل وتجهيز الإصدار بعد مراجعات السلامة وقبول المالك.
تصمم حدود المزامنة والأمان منذ البداية، وتختبر كل حزمة عند تنفيذها. فحص أدوات CI الناجح لا يعني نجاح بناء التطبيق أو اختبارات سلوكه. حماية الفرع والفحوص الإلزامية بوابة جودة قبل اعتبار البناء الإنتاجي معتمدًا، ولا تمنع إثباتًا تجريبيًا محدودًا على فرع معزول.
